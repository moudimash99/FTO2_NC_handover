Read this first

You have taken over the code of the FTO2 NC dashboard. You do not need to read this manual from end to end. Read this chapter: it takes ten minutes. Keep chapter 2 for the day something breaks. The rest is a reference, to open at the page you need.

What it is

The whole system is two things: a notebook that writes four tables, and a Slate application that reads them. There is no server and no database of its own. Nothing runs by itself except the copy of the four tables to the database Slate reads.

Three kinds of things, and where each one lives

WhatWhere it runs in SkywiseWhere its original is

The program

The rule to remember For the program and the pages, Skywise holds copies and the source folder holds the original. A change typed directly into notebook_kit or into a Slate sandbox works, and is lost at the next installation. Make the change in the source, run the checks, build, then install (chapter 7). For the settings it is the opposite: the original is data/config/ in Skywise. Never upload the folder config of the source over it.

Two ways of working

In Skywise only. Enough for everything that is a setting, and to repair: read the notebook's message, correct a table, put a page's previous code back. You need a browser and the rights of the Access guide.

With the source folder on a computer. Needed to change the program or the pages. The folder holds the code, the data of a reference day, and checks that compare every figure of the pages with that reference: a change that moves a number it should not move is caught before it reaches Skywise. You need Python 3 and Node.js; chapter 8 says how to build and check.

What is not finished, and what to know

SubjectThe state of things
The cause of new defectsThe cause of each defect line is stored in the dataset fto2_ai_labels. These labels were made in two passes (12 October and 4 November 2026) by a language model reading the full text of each NC with the definitions of the tab Définitions, followed by two review passes. A line written or changed since then is classified by the defect reader of the program, a set of rules: on the lines that have both, it gives the same category as the stored label for 94 % of them and the same cause for 88 %. Nothing has to be done for the dashboard to stay complete. Each run writes the lines waiting for a label in fto2_lines_to_label.csv; labelling them again needs a tool approved by IT for the NC texts (chapter 4).
The beginning of each yearThe alarms compare the last weeks with the weeks before, inside the year followed. Until the year has sixteen finished weeks (late April) the bell says that it has not enough weeks, and an MFT action started in the first weeks of the year has no reference. It is by design; looking back into the previous year would remove it and is not done.
The MFT actionsThe shared list is the table 1_actions_mft.csv. Slate gives a code sandbox no shared storage, so an action typed on the page stays in that browser until someone adds it to the table.
The run is manualSomeone runs the notebook. The program can also run as a scheduled transform of a Code Repository (fto2/transform_io.py prepares it); this was not put in place.
The A400MThe text of its NCs is not available in Skywise: they count as NCs and in the cost, and no defect is read.
The aléasThe extract of MES Disruptions used to build the program stopped at exactly 2,500 rows. If the number of aléas of a year stays at a round number, look for a limit on that dataset.
The part pricesOnly the parts whose price is typed in 1_prix_pieces.csv are valued. Each run lists the parts still to price in fto2_parts_to_price.csv.
The former applicationWhile garder_anciennes_sorties is oui in 2_parametres.csv, the notebook also writes the four tables of the former Slate application. Set it to non once that application is retired.

When something breaks

Start from what you see. Each row sends you to the place where the cause usually is. Nothing here needs the source folder: everything is done in Skywise.

The notebook stops

The notebook checks the settings first, in less than a second, before it reads or writes anything. A run that stops there has changed nothing: the dashboard still shows the previous run.

The last messageWhat it meansWhat to do
Names a file of data/config/ and a line.A settings table is badly filled: a ; typed in a cell, a date, a word that is not one of the allowed ones.Correct that line. The message says what is expected. Chapter 3, "The basics".
"settings table … not found"A table was renamed, moved or deleted.Put it back in data/config/, from the folder config of the installation.
A dataset name that is not found.The dataset is not in the Data panel of the workspace under that name.Add it in the Data panel with the name of chapter 7, or change the name in 2_sources.csv.
A permission error on a dataset.The person who runs the notebook lacks access.The Access guide, chapter 5.
"… is not a price"Text in the price column of 1_prix_pieces.csv.Correct that line.
"fto2_dash_cout not written"Normal: that table only serves an optional set-up.Nothing.
A warning ⚠️ at the end, about the year.The clock is in a new year and the settings still follow the previous one.The new-year list of the Settings guide, chapter 7.
Any other error.The last step printed says how far the run went.Chapter 4, "The run, step by step", gives the file of each step.

If the same error comes back after a correction, restart the kernel of the notebook and run every cell again: Python keeps in memory what it has already loaded.

The figures are old

The date Données au… at the top of the page is the day of the latest NC the page received. Follow the chain from left to right and stop at the first link that is late.

  1. The notebook. When was it last run, and did it reach its last lines, the list of the tables written? If not: run it, or see section 2.1.
  2. The four datasets. Open fto2_dash_nc in Skywise: its last update must be the time of the run.
  3. The sync to Postgres. In Slate, run the query q_fto2_nc and look at the most recent created. If the dataset is up to date and the query is not, the sync has not run: start it, and find out why it did not follow the update.
  4. The browser. Reload the page.

If the notebook ran and the latest NCs are still missing, look at the source: the dataset Non Conformity itself may be late.

A figure looks wrong

Before opening any code, use what the page gives.

  1. Is it the selection? Click ⓘ Comment la sélection est faite: the page shows what each filter removed. Most "wrong totals" end here.
  2. Is it one NC? Find it in the list at the bottom of the tab. Its line, product, type and decision are the result of the rule tables. For its cost, Coût de non-qualité › Expliquer le calcul shows every step.
  3. Which rule decided? Each label of an NC comes from one rule table of group 2 (2_regle_…csv): the first rule that matches wins. Chapter 3 lists the tables and what each decides.
  4. Which code reads a table? The file lisez_moi.csv of the settings has a column lu_par: the file of the program that reads each table. From a table to the code that uses it, start there.
  5. Is it the calculation? Chapter 4 for what the notebook computes; chapter 5 for what the page computes: rates, targets, forecasts and alarms are computed in the page.

After a repair

  • A setting was corrected: run the notebook, reload the page, compare the key figures with what you expected.
  • Code was put back or changed in Skywise: note it, and bring the same change into the source folder; otherwise the next installation removes it.
  • The program or a page was changed in the source: run the checks of chapter 8 before installing.
