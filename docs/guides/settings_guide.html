The idea in one page

The dashboard keeps itself up to date from Skywise. A few things cannot be read from Skywise and are yours to keep up to date. This guide lists them all, and shows how to change each one. No knowledge of code is needed.

There are only three kinds of things:

KindWhat it isWhat you do
Files you saveFour files that the team already downloads elsewhere: the production plan, the cable team's tracker, the GPS register, the Test list.Save the new download in the folder data. Nothing to type.
Six small tablesWhat is decided, not computed: the year followed, the target, the hourly rates, the shutdown days, the part prices, the MFT actions. Their names start with 1_.Change a value, or add a line.
Everything elseThe rules that sort the NCs, the names, the program itself.Leave it. It belongs to the person who maintains the code.

After any change, run the notebook (chapter 6). It reads everything again and rebuilds the dashboard's data. If something is wrong in a file or a table, the notebook stops and says, in plain words, which file, which line and what to write. Nothing on the dashboard is changed until the notebook has run to the end, so a mistake cannot damage what the team sees.

How often
  • New NCs: run the notebook, as often as the team wants fresh figures.
  • Production plan and cable tracker: save a new download when it has changed; once a month is a good habit.
  • Rates, target, prices, actions: only when they change.
  • Once a year, in January: the new-year list of chapter 7. It takes ten minutes.

The production plan, in detail

This is the one that matters most, because every rate of the dashboard is "NCs per aircraft built".

  1. Open the Tableau Avances / Retards and download it as CSV.
  2. Name the file Avances_Retards_ followed by today's date written year-month-day, for example Avances_Retards_2027-01-12.csv. If you leave the date out, the day the file was saved is used.
  3. Save it in data/, beside the earlier exports.
  4. Run the notebook. Its last lines say which exports were read: 
    production plan: 1059 aircraft and products, as of 2026-11-03 (exports read: Avances_Retards_2026-10-07.csv, Avances_Retards_2026-11-03.csv)
Never delete the earlier exports

The Tableau Avances / Retards only lists recent aircraft: one delivered months ago disappears from it. The notebook reads all the exports of the folder, so it remembers those aircraft. They are needed: next year's targets start from what was delivered this year. Deleting old exports would lose that.

How the exports are put together, for the curious: for each aircraft and product, the newest export wins. An aircraft that a newer export no longer lists is kept if it had been delivered by then; if it left the plan before being delivered (a cancelled or renumbered aircraft), it is dropped.

How to change a table

A table is a small text file ending in .csv. It opens in Excel like a spreadsheet: the first row holds the column names, each row below is one entry.

The steps

  1. In the Code Workspace, open the folder data/config/ and download the table (right-click, Download).
  2. Open it in Excel. Change what you need (chapter 5 says what, table by table).
  3. Save it with the same name, as CSV UTF-8 or as CSV (séparateur : point-virgule). If Excel asks whether to keep the format, answer yes.
  4. Upload it back into data/config/, replacing the old one.
  5. Run the notebook (chapter 6) and look at the dashboard.

A table can also be changed directly in the workspace, by opening it as text: each line is a row, and the columns are separated by a semicolon.

The rules that keep a table readable

RuleWhy, and what happens otherwise
Never change the first row.The notebook finds the columns by their names. A renamed column stops the run: "the column(s) … are missing".
In a "nom / valeur" table, change only valeur.The notebook looks for each line by its nom. A renamed or deleted line stops the run: "the line '…' is missing".
Keep the file's name.Excel sometimes adds "(1)" to a downloaded file. The table must go back under its exact name.
Numbers: 0.25 or 0,25.Both are read. No unit in the cell: 123, not "123 €".
Dates: 2026-12-24 or 24/12/2026.Both are read. Excel turns the first into the second when it saves: that is fine.
Several values in one cell: separated by |.For example 7=0.6|8=0.6.
The description column is for people.The notebook ignores it. Write there anything useful to the next person.
Nothing can be broken for good

The notebook checks every table before it computes anything. If a value is not of the right kind, it stops with a message (chapter 8) and the dashboard keeps showing what it showed before. Correct the table and run again.

A rate changes the whole year

The cost of every NC of the year followed, and of the comparison year, is computed again with the new values. The figures of last month will not be the ones shown last month. Note the total cost before and after the change, to be able to explain the difference.

Long numbers in Excel

Excel shows a long number such as 92513600000200 as 9,25136E+13 and saves it that way: the part would never be found. Before typing or pasting material numbers, select the column and set its format to Texte. If it happens anyway, the notebook stops and names the line.

A price list exported from another tool can be used as it is, if it has a column for the material number and one for the unit price: save it under the name 1_prix_pieces.csv.

Each January: starting the new year

The dashboard follows one year at a time. In January, five small things move it to the new year.

  • The year. In 1_parametres.csv, write the new year on the line annee (section 5.1).
  • The production plan. Save a fresh export of the Tableau Avances / Retards in data/, beside the earlier ones (section 3.1).
  • The GPS register. Save the new year's register in data/ under the same name with the new year (section 3.3).
  • The shutdown days. Add the new year's closures to 1_calendrier_production.csv (section 5.4).
  • The target. If it changes for the new year, objectif_baisse in 1_reglages_pages.csv (section 5.2).

Then run the notebook. Nothing else changes anywhere: the comparison year becomes the year just ended, its deliveries are counted from the production plan, the targets follow, and every text of the pages names the new years.

What to expect in the first weeks of a year
  • The dashboard shows few NCs at first: it only counts the new year.
  • The bell stays quiet until late April. It compares the last 4 weeks with the 12 weeks before, inside the year; until the year has 16 full weeks, it says "Pas encore assez de semaines pour comparer". This is expected.
  • On the MFT page, the comparison with "the weeks before" starts again from the first weeks of January.

There is no hurry on 1 January: until the year's line is changed, the dashboard keeps showing the year just ended, complete, which is convenient for the year's review.

Any other message

If the message does not name one of your files, or talks about something this guide does not cover (a dataset, a permission, a line of program), do not try to correct it. Copy the last twenty lines printed and send them to the person who maintains the code. The dashboard keeps showing its last good data in the meantime.
