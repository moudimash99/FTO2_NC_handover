What you take over

The FTO2 NC dashboard follows the non-conformities (NCs) of the plant: how many, what kind, what they cost, and whether the year is on target. It lives entirely in Skywise. The team only opens the pages; everything behind them is yours.

It is made of five parts, one after the other:

PartWhat it is
The settingsThe values people fill in by hand (target, rates, blackout days, part prices, lists) in the Fusion spreadsheet FTO2 NC Dashboard - Settings, and the rules (which NC counts, which product, which cause) in small tables kept with the code.
The updateThe pipeline: Python code that reads the NCs from Skywise, applies the rules, reads the defects written in each NC, works out their cost, and writes four tables. It runs as a transform of a Code Repository, on a schedule, or by hand from the pipeline notebook: the same code either way.
The four tablesfto2_dash_nc (one row per NC), fto2_dash_defects (one row per defect), fto2_dash_disruptions (quality aléas with no NC) and fto2_dash_ref (everything else the pages need).
The syncThe four tables are copied to Postgres, where the Slate pages can read them.
The pagesA Slate application: the dashboard, the MFT page, the Tableau Elizabeth, and the NC writer, which helps write an NC to the standard.

One rule explains most of the design

The update decides and calculates; the pages only filter, add up and draw. Which NC counts, what each defect is, what it costs: all of it is decided once, in the update. The pages never recompute it. So a number that is wrong everywhere is an update question; a number wrong on one chart only is a page question.

A second rule follows from it: no business value in the code. A rate, a date, a product name or a threshold belongs in a settings table, not in the code. Most change requests are therefore a line in a table, not a code change.

Who changes what

WhoWhat they change
Head of QualityThe decided values: the cut of the target, the hourly rates and minutes, the blackout days, last year's deliveries, the planned volume, the plant code. In the Fusion spreadsheet.
Configuration managerThe values that follow the work: part prices, the cable tracker, the GPS register, the Test list. In the Fusion spreadsheet. Also the rule tables, with care.
Developer (you)The code of the update and of the pages, the technical tables, the access rights, and help to the two others when a value does not do what they expect.

The year followed changes by itself on 1 January: nobody has to touch it.

Your first week

  1. Check you can open every part listed above, with your own account (Skywise: access and ownership).
  2. Run the update once from start to end and read what it prints (The pipeline).
  3. Open the dashboard and check that the date Données au… at the top moved to the day of the latest NC.
  4. Open the pages in edit mode and find the code of one chart (The front end).
  5. Read Known limits and open work: it lists what is known to be imperfect, so you don't rediscover it.

The documents of this folder

  • Configuration: the settings, who fills which, and what each one changes.
  • The pipeline: how the update works, how to run it, and what to do when it stops.
  • The front end: how a page gets its data, how to change a chart, the bell, and the boxes a page can show.
  • Skywise: access and ownership: every object, who needs which right, and what to check before someone leaves.
  • Checking a change, and Known limits and open work.
