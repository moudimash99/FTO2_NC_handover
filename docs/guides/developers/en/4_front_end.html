The pages

The Slate application holds the dashboard, the MFT page and the Tableau Elizabeth. Each page is one Slate code sandbox in four parts: CSS (the look), HTML (the frame, one empty box per chart), JS (plain JavaScript, no outside library) and State (the links to the queries). The pages only filter, add up and draw; every number they show was decided by the update.

How a page gets its data

  1. The queries q_fto2_nc, q_fto2_def, q_fto2_dis and q_fto2_ref read the four tables in Postgres (schema foundry_sync). Their SQL only lists the columns.
  2. The State of the sandbox gives each result a name the page knows: nc, def, dis, ref.
  3. The loader, at the very end of the JS, waits until all four have arrived, then starts the page. If one stays missing, it shows a box naming it.
  4. The reference data arrives in pieces; fto2RefBlocks glues them back into one block per page.
  5. The adapter fto2FromTables turns the tables into the page's own lists, D.ncs and D.defects, each row a list of values by position. The positions are listed there, next to the column each one comes from.

What happens on a click

The filters are kept in one object, GF. A change goes through setGF, which calls select() to make the lists of NCs on screen (SEL_NC: everything the filters keep; SER_NC: the plant's own NCs; CLI_NC: the customer returns), then renderAll() redraws. A click on a chart works through the attribute data-pick on the drawn element; a tooltip through data-tip.

Changing a chart

  • Where it is placed: V2L lists the cards of each tab by key. Move a key to move a chart; remove it to hide the chart.
  • Which code draws it: a letter key (VT, VN…) is drawn by the function named in V2F; a number by the function given in PSPEC; a key starting with a: by RV_ANA. The quickest way: search a few words of the chart's title in the JS; they lead to its key.
  • Changing it: keep counting from SEL_NC so the filters apply, and put every new text in STR, in both languages.
  • Adding one: copy a similar chart's function under a new key, add the key to V2F, its titles to GSTR, and the key to V2L.
  • Download: the most important charts have a PNG button that saves them as an image. A new chart gets one by adding its key to V2PNG.

The tables hold two years: the comparison year and the year followed. Each page chooses what it shows: the dashboard and the Tableau Elizabeth keep the year followed (the adapter drops the rest), the MFT page keeps both, so that a week, a month or an action is compared with the weeks before it across the new year. The page holds no year of its own: the years come with the settings, and the texts write them as {YEAR} and {PREV}. The names y25 and v26 in the code date from the first year followed: read them as "the comparison year" and "the year followed".

The calendar on the pages

The pages take the working time from the blackout days, through the reference data: the weight of every day and of every ISO week of the year. A week under semaine_faible_moins_de (60 % of a normal week) is a closure week, left out of the averages and the references on every page (calW). The month in progress counts the share of its working time gone (dayShare), not of its calendar days. Texts that name last year's volume write it through withYears: "delivered" while it comes from the 2025 deliveries table, "built" once it is measured from the plan.

The bell

Line by line, the bell compares the defects of the last 4 finished weeks with the 12 weeks before, per aircraft built, and rings when the rise is too big to be chance. It also catches slow rises and aircraft with far more NCs than usual. Its settings are in 3_alarmes.csv. The MFT page has its own copy of the alarm engine: a change to one must be made to the other, or the two pages will ring differently.

The MFT page and the Tableau Elizabeth

Both read the same tables through their own, simpler adapter. The MFT page shows one line at a time: the week's Pareto, the analysis, and the follow-up of the MFT actions. The Tableau Elizabeth shows a line's NCs in three families, with the weeks above a threshold.

The NC writer

The NC writer is a page of its own that helps write an NC to the standard. When the text is ready, it fills a Slate variable through an event, and the action of the object type a30 Nc Writer Dataset saves it with the values of that variable. Its lists (products, defects, causes) are at the top of its JS, in one settings object.

Three rules for code in Slate

  • Never two { in a row in the JS. Slate reads them as a link to a query and breaks the code.
  • Every CSS rule starts with .fto2, so the styles stay inside the sandbox.
  • No data in the code. A list or a value someone may want to change belongs in a setting, read by the update and passed to the page.

Before any change, copy the current JS out of the sandbox and keep it: it is your way back. Slate's editor is slow with a file this long; edit in a text editor and paste it back.

When a page shows a box

The box saysWhere to look
Still waiting for a query, with its nameThe query's name and SQL in Slate
The query returned no rowThe sync, then the update's last run
No readable NC, with the columns receivedThe query returns columns the page does not expect: compare with the table
Exactly N rows receivedA row limit on the query: Slate cut the result
An error with a line of codeThe JS has a mistake: paste the previous version back

An empty page with no box at all is usually a rights problem: the person can open the application but not the four tables (Skywise: access and ownership).
