Ce que vous reprenez

Le tableau de bord NC FTO2 suit les non-conformités (NC) de l’usine : combien, de quelle nature, ce qu’elles coûtent, et si l’année est dans l’objectif. Il vit entièrement dans Skywise. L’équipe ne fait qu’ouvrir les pages ; tout ce qu’il y a derrière est à vous.

Il est fait de cinq parties, l’une après l’autre :

PartieCe que c’est
Les réglagesLes valeurs que des personnes remplissent à la main (objectif, taux, jours de fermeture, prix des pièces, listes) dans le classeur Fusion FTO2 NC Dashboard - Settings, et les règles (quelle NC compte, quel produit, quelle cause) dans de petites tables gardées avec le code.
La mise à jourLe pipeline : du code Python qui lit les NC dans Skywise, applique les règles, lit les défauts écrits dans chaque NC, calcule leur coût et écrit quatre tables. Il tourne comme un transform d’un Code Repository, de façon planifiée, ou à la main depuis le notebook du pipeline : le même code dans les deux cas.
Les quatre tablesfto2_dash_nc (une ligne par NC), fto2_dash_defects (une ligne par défaut), fto2_dash_disruptions (les aléas qualité sans NC) et fto2_dash_ref (tout le reste dont les pages ont besoin).
La synchronisationLes quatre tables sont copiées dans Postgres, où les pages Slate peuvent les lire.
Les pagesUne application Slate : le tableau de bord, la page MFT, le Tableau Elizabeth, et la Saisie structurée de NC, qui aide à rédiger une NC selon le standard.

Une règle explique l’essentiel de la conception

La mise à jour décide et calcule ; les pages ne font que filtrer, additionner et dessiner. Quelle NC compte, ce qu’est chaque défaut, ce qu’il coûte : tout est décidé une seule fois, dans la mise à jour. Les pages ne le recalculent jamais. Un chiffre faux partout est donc une question de mise à jour ; un chiffre faux sur un seul graphique est une question de page.

Une deuxième règle en découle : aucune valeur métier dans le code. Un taux, une date, un nom de produit ou un seuil a sa place dans une table de réglages, pas dans le code. La plupart des demandes de changement sont donc une ligne dans une table, pas une modification du code.

Qui change quoi

QuiCe qu’il change
Responsable qualitéLes valeurs décidées : la baisse visée par l’objectif, les taux horaires et les minutes, les jours de fermeture, les livraisons de l’an dernier, le volume prévu, le code de l’usine. Dans le classeur Fusion.
Gestionnaire de configurationLes valeurs qui évoluent avec le travail : les prix des pièces, le suivi des câbles, le registre GPS, la liste Test. Dans le classeur Fusion. Aussi les tables de règles, avec prudence.
Développeur (vous)Le code de la mise à jour et des pages, les tables techniques, les droits d’accès, et l’aide aux deux autres quand une valeur ne fait pas ce qu’ils attendent.

L’année suivie change toute seule le 1er janvier : personne n’a à y toucher.

Votre première semaine

  1. Vérifiez que vous pouvez ouvrir chacune des parties listées ci-dessus, avec votre propre compte (Skywise : accès et propriété).
  2. Lancez la mise à jour une fois, du début à la fin, et lisez ce qu’elle affiche (Le pipeline).
  3. Ouvrez le tableau de bord et vérifiez que la date Données au…, en haut, est passée au jour de la dernière NC.
  4. Ouvrez les pages en mode édition et trouvez le code d’un graphique (Les pages).
  5. Lisez Limites connues et travail en cours : ce document liste ce que l’on sait imparfait, pour vous éviter de le redécouvrir.

Les documents de ce dossier

  • Configuration : les réglages, qui remplit lesquels, et ce que change chacun.
  • Le pipeline : comment fonctionne la mise à jour, comment la lancer, et que faire quand elle s’arrête.
  • Les pages : comment une page reçoit ses données, comment modifier un graphique, la cloche, et les encadrés qu’une page peut afficher.
  • Skywise : accès et propriété : chaque objet, qui a besoin de quel droit, et que vérifier avant un départ.
  • Vérifier une modification, et Limites connues et travail en cours.
