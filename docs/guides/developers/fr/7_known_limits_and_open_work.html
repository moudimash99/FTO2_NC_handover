Limites connues

Elles sont connues, et acceptées pour l’instant. Le document des utilisateurs Limites connues explique celles qu’ils peuvent voir.

LimiteCe que cela veut dire
Nouvelles lignes de défautUne ligne de défaut reçoit sa cause précise quand elle est étiquetée. D’ici là, elle garde la cause du lecteur de défauts, un peu moins précise. Chaque mise à jour liste les lignes encore à étiqueter.
L’A400MSes NC arrivent dans Skywise sans leur texte. Une ligne de défaut est tirée du titre quand une règle le reconnaît ; sinon, la NC compte, sans défaut.
Le coût est une estimationFait pour comparer causes, lignes et mois, pas pour être comptabilisé. Il n’a pas été comparé avec la méthode officielle d’Airbus.
Prix des piècesBeaucoup de pièces n’ont pas encore de prix : leurs NC comptent sans la valeur de la pièce. Chaque mise à jour les liste, les plus fréquentes d’abord.
Numéros de matériel dans FusionUn numéro de matériel tapé comme un nombre perd ses zéros de tête. La mise à jour rapproche les numéros sans leurs zéros de tête, mais gardez la colonne en texte dans la feuille.
Début janvierL’année suivie change seule le 1er janvier : le tableau de bord démarre donc presque vide. La cloche reste muette les 16 premières semaines (fin avril).
Deux copies de la clocheLe tableau de bord et la page MFT ont chacun leur propre copie du moteur d’alarmes. Une modification de l’une doit être faite aussi dans l’autre.
Les objectifs 20262025 est compté en produits livrés (le plan ne remonte pas jusqu’à 2025), 2026 en produits fabriqués sur les jours ouvrés : les taux diffèrent de quelques pour cent par ligne (environ 6 % sur l’A320). À partir de 2027, les deux années sont mesurées à partir du plan, de la même façon.
Le type de NC de l’an dernierLes deux années passent par les mêmes étapes, mais seul le registre GPS de cette année est lu : les NC de l’an dernier prennent leur type de la table de règles, celles de cette année du registre quand il les liste. Le type change quelques règles de coût (contrôle final, travail interne).
NC suppriméesComptées, par décision : le travail qu’elles ont causé a été fait. Elles ont leur propre type de NC (Qualité), et forment donc leur propre barre par lieu de détection. Dans la vue par défaut, elles font environ 5 % des NC de cette année (8 % l’an dernier) et 1,5 % des défauts : trop peu pour changer le Pareto. Certaines sont des copies d’une NC active, comptées deux fois.
Les aléas de décembre dernierLus seulement pour relier les NC de début janvier ; ils ne sont pas comptés comme aléas sans NC.

Travail en cours

SujetOù on en est
L’an dernier sur le tableau de bordLes tables contiennent maintenant les NC de l’an dernier, que la page MFT utilise. Le tableau de bord ne montre toujours que l’année suivie ; une vue sur 12 mois à cheval sur deux années, ou une cloche qui fonctionne dès janvier, les liraient aussi.
Un seul endroit pour chaque règleEncore écrites deux fois : les groupes « Responsabilité » (la table 2_regle_responsabilite.csv pour l’an dernier, la copie propre aux pages pour cette année) ; le code de l’usine (règles, réglages du coût, pages) ; les noms des lieux de détection et des décisions (les pages les traduisent avec leurs propres listes) ; l’arbre des causes (décidé dans le code du lecteur de défauts, décrit dans 3_sous_categories.csv : la mise à jour s’arrête si les deux diffèrent). Pour chacune : la calculer une seule fois dans la mise à jour et l’envoyer aux pages.
Lancer la mise à jour de façon planifiéeLa mise à jour tourne comme transform du Code Repository, de façon planifiée (le README du kit Code Repository). Dès qu’elle écrit les tables que lisent les pages (son étape 11), le notebook n’est plus qu’une solution de secours : le code se change dans le repository seulement.
Étiqueter les nouvelles lignes de défautLes lignes à étiqueter sont listées à chaque mise à jour. Aucun texte de NC ne peut sortir de Skywise vers un outil extérieur sans l’accord de l’IT et du propriétaire des données.
Actions MFT gardées pour tousEn cours de mise en place sur la page MFT dans Skywise (le README de l’installation Skywise, étape 4) : les actions sont gardées dans un objet du type d’objet de la Saisie structurée de NC, et enregistrées pour tous en un clic (l’enregistrement de la page remplit une variable, qui soumet l’action). Reste à régler : la relecture des actions enregistrées. La copie Postgres des données du type d’objet a du retard sur l’Ontologie, et la source « foundry » de Slate n’a pas atteint l’API qui lit directement les objets. D’ici là, une action modifiée sur la page n’est pas gardée. La cloche du tableau de bord ne connaît encore que les actions de la table.
Les anciennes sortiesTant que la ligne garder_anciennes_sorties vaut oui, la mise à jour écrit encore les tables de l’ancienne application Slate. Passez-la à non dès que plus personne n’utilise cette application.
Les calculs en fonctions SlateLes objectifs, la cloche et l’explication du coût peuvent aussi tourner comme fonctions Slate, au lieu de tourner dans la page. Prêt, et vérifié : les chiffres sont les mêmes ; pas essayé dans Skywise. Les pages fonctionnent sans.
Une table de référence plus proprefto2_dash_ref contient de grands blocs de texte découpés en morceaux. Cela fonctionne, mais une table par sujet serait plus facile à lire. Pas urgent.
